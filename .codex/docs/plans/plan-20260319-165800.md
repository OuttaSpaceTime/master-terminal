# Git Hook Plan: Auto-run `bundle exec rubocop -A` For Ruby Projects

Mode: Direct planning with minimal discovery
Date: 2026-03-19 16:58 CET

## Objective

Add a Git hook workflow for this machine that automatically runs `bundle exec rubocop -A` when committing in Ruby projects, without affecting non-Ruby repositories.

## Source Request

> please setup a git hook for me that always run bundle exec rubocop -A for ruby projects, let's first plan how to do this.

## Discovery Summary

Known facts:
- The current working directory `/home/felix/Code/Misc/spaced-repitition` is not a Git repository.
- Global Git hooks are already configured via `core.hooksPath=/home/felix/.githooks`.
- `~/.githooks` already exists and currently contains an empty `pre-push` hook.
- `bundle` and `ruby` are available through `rbenv` shims.
- This setup suggests the right implementation target is a global hook script in `~/.githooks`, not a repo-local `.git/hooks` file.

Inferences:
- The user wants a machine-wide behavior for all Ruby repos, not a one-off hook in the current repo.
- The correct hook is almost certainly `pre-commit`, not `pre-push`, because the goal is to auto-format before code is committed.
- Running `rubocop -A` against the whole repo on every commit would be too invasive and too slow; the safer behavior is to target staged Ruby files only.

Unresolved but non-blocking assumptions:
- Some Ruby projects may not have `rubocop` in their bundle. The hook should fail softly or skip in those repos.
- Some projects may rely on `.ruby-version` and Bundler environment resolution. The hook should preserve the repo-local environment and run from repo root.

## Recommended Design

Use a global `pre-commit` hook under `~/.githooks/pre-commit` with Ruby-project detection and staged-file filtering.

### Why this is the right shape

- It reuses the existing global Git hook topology already configured on the machine.
- It applies uniformly across repos without modifying each repository.
- It can cheaply detect Ruby repos and no-op elsewhere.
- It can operate only on staged Ruby files, which is safer than rewriting unrelated files in the repo.

## Scope Guardrails

In scope:
- Add a global `pre-commit` hook in `~/.githooks`.
- Detect whether the current repository is a Ruby project.
- Detect staged Ruby files.
- Run `bundle exec rubocop -A` against those staged Ruby files only.
- Re-stage any files modified by RuboCop.
- Exit non-zero if RuboCop still fails after autocorrect.

Out of scope:
- Installing RuboCop in repos that do not already have it.
- Managing per-project RuboCop configs.
- Running formatting on push instead of commit.
- Auto-formatting non-Ruby files.

## Current Behavior

Before implementation:
- Git commits do not automatically format Ruby files via a global pre-commit hook.
- There is no existing `pre-commit` hook in `~/.githooks`.
- Non-Ruby repos and Ruby repos behave the same with respect to commit-time formatting.

## Planned Behavior

After implementation:
- On `git commit`, Git invokes `~/.githooks/pre-commit`.
- The hook detects the repo root.
- The hook checks whether the repo looks like a Ruby project, using markers such as `Gemfile`.
- If not a Ruby project, it exits successfully without doing anything.
- If it is a Ruby project, it computes staged Ruby files from the index.
- If no staged Ruby files exist, it exits successfully.
- If staged Ruby files exist, it runs `bundle exec rubocop -A -- <files...>` from the repo root.
- If RuboCop rewrites files, the hook re-stages those same files.
- If RuboCop finishes cleanly, commit proceeds.
- If RuboCop still fails, commit is blocked and the user sees the RuboCop output.

## Execution Flow Delta

### Before
1. User runs `git commit`.
2. No pre-commit formatter enforces Ruby autocorrect globally.
3. Commit proceeds regardless of Ruby formatting state unless repo-local hooks exist.

### After
1. User runs `git commit`.
2. Global `pre-commit` hook starts.
3. Hook finds repo root with Git.
4. Hook checks for Ruby markers, primarily `Gemfile`.
5. Hook gathers staged Ruby files from the index.
6. Hook runs Bundler-scoped RuboCop autocorrect on those files only.
7. Hook re-stages changed files.
8. Hook exits 0 on success or non-zero on unresolved RuboCop failure.
9. Commit proceeds only if the formatting step closes cleanly.

Loop closure signal:
- Successful commit after hook execution, with staged Ruby files rewritten and re-added to the index as needed.

## Compatibility Assessment

### Safe cases
- Ruby repo with `Gemfile` and `rubocop` in bundle.
- Repo with staged `.rb`, `.rake`, `Gemfile`, `Rakefile`, or similar Ruby targets.
- Repo using `.ruby-version`; Bundler should resolve through the developer's existing shell/rbenv path.

### Risky cases
- Ruby repo without `rubocop` in the bundle.
- Repo with custom wrapper commands where `bundle exec rubocop` is not the intended invocation.
- Commits containing many staged Ruby files, where `rubocop -A` may be slow.
- Auto-correction that changes files semantically or creates new offenses requiring review.

### Recommended safety choice

Fail-soft on environment mismatch:
- If `Gemfile` exists but `bundle exec rubocop` is unavailable or returns a clear “gem not found” setup error, print a short warning and skip formatting rather than blocking all commits globally.

This is the best default for a machine-wide hook because it avoids breaking Ruby repos that have not adopted RuboCop.

Alternative stricter mode:
- Block commit if a Ruby repo lacks working RuboCop.

I do **not** recommend this as the initial default for a global hook.

## Implementation Steps

1. Create `~/.githooks/pre-commit` as an executable POSIX shell script.
2. Determine repo root with `git rev-parse --show-toplevel`; exit if unavailable.
3. `cd` to repo root so Bundler and `.ruby-version` resolution happen in the project context.
4. Detect Ruby project via `Gemfile` presence.
5. Gather staged files with `git diff --cached --name-only --diff-filter=ACMR`.
6. Filter that list to Ruby-relevant paths and extensions.
7. If no Ruby files are staged, exit 0.
8. Verify RuboCop availability via `bundle exec rubocop --version` or equivalent lightweight probe.
9. If RuboCop is unavailable, print a short skip message and exit 0.
10. Run `bundle exec rubocop -A -- <staged ruby files>`.
11. If command succeeds, `git add -- <same files>`.
12. If command fails, exit non-zero so the user can inspect/fix remaining offenses.

## File Matching Strategy

Recommended staged-file match set:
- `*.rb`
- `*.rake`
- `Gemfile`
- `Rakefile`
- `Guardfile`
- `Capfile`
- optionally `*.gemspec`

This covers normal Ruby repos without overmatching too much.

Finish signals:

- Commits in Ruby repos trigger staged-file RuboCop autocorrect.
- Non-Ruby repos are unaffected.
- Modified Ruby files are re-staged automatically.
- Missing-RuboCop repos are skipped cleanly instead of causing global breakage.

## Draft Hook Shape

```sh
#!/bin/sh
set -eu

repo_root=$(git rev-parse --show-toplevel 2>/dev/null) || exit 0
cd "$repo_root"

[ -f Gemfile ] || exit 0

staged_files=$(git diff --cached --name-only --diff-filter=ACMR)
[ -n "$staged_files" ] || exit 0

ruby_files=$(printf '%s\n' "$staged_files" | grep -E '(^Gemfile$|^Rakefile$|^Capfile$|^Guardfile$|\.gemspec$|\.rake$|\.rb$)' || true)
[ -n "$ruby_files" ] || exit 0

if ! bundle exec rubocop --version >/dev/null 2>&1; then
  echo "pre-commit: skipping RuboCop; bundle exec rubocop is unavailable in this repo" >&2
  exit 0
fi

# shellcheck disable=SC2086
bundle exec rubocop -A -- $ruby_files
# shellcheck disable=SC2086
git add -- $ruby_files
```

## Tradeoffs

### Recommended approach
Global `pre-commit` hook with Ruby-project detection and staged-file formatting only.

Pros:
- one-time setup
- low friction in daily use
- safe for non-Ruby repos
- minimal rewrite scope

Cons:
- shell quoting must be handled carefully for unusual filenames
- hook latency depends on RuboCop speed
- auto-correction during commit may sometimes surprise the user

### Alternative approach
Repo-local hooks or pre-commit framework.

Pros:
- more explicit per-repo control
- easier to version with the codebase

Cons:
- not what the current request implies
- requires repeated setup across repos

## Recommendation

Implement the global `pre-commit` hook in `~/.githooks` with these defaults:
- only activate in repos with `Gemfile`
- only inspect staged Ruby files
- run `bundle exec rubocop -A` on those files
- re-stage them
- skip cleanly if RuboCop is unavailable in that repo

This gives the desired machine-wide behavior without forcing project dependency changes or impacting non-Ruby repositories.
